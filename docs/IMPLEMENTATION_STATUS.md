Mis à jour le **7 septembre 2026**, après le lot 35 sur `codex/prod-ready`. Dernière recette générale : 60 parcours au lot 33 ; quatre parcours ciblés au lot 35.

**La préparation à la production est en cours.** Le dépôt possède les fonctionnalités et les preuves locales ci-dessous. Le candidat courant n’a pas été déployé ni certifié auprès des prestataires par cette exécution. Les validations d’août ne valent pas validation du code de septembre. L’ancien registre est conservé dans [l’archive datée](./audits/implementation-status-before-2026-09-07-refresh.md).

Le [plan T00–T23](./PLAN_PROD_READY.md) fixe le périmètre ; le [journal d’exécution](./PROD_READY_EXECUTION.md) relie chaque livraison à ses preuves. Une fonction présente dans le code, une recette locale réussie et une intégration réellement certifiée sont trois états distincts. Aucun pourcentage « 100 % fonctionnel » n’est déduit d’un nombre de tests.

## Dix modèles de vigies

La source est `web/src/lib/monitoring.ts` : absence de diffusion, dépenses sans conversion, CPA élevé, pression budgétaire, requêtes coûteuses sans conversion, Quality Score faible, annonces responsives faibles/refusées, écart de tracking, écart de pacing et dépassement prévisionnel. Les seuils sont configurables ; leur présence n’est pas une garantie de résultat publicitaire.
